# Agent Note: 复用图片附件实现浏览器文件输入

Status: implemented

English | [中文](2026-08-14-composer-file-intake.md)

## Problem

Web 输入栏此前只接受粘贴和拖放的图片，缺少选文件入口。文本和源码文件没有进入提示词的可用路径，纯文本模型路由也无法直接消费原始视频文件。

## Decision

输入栏在命令启动按钮旁提供回形针文件选择器。图片继续走既有的持久附件路径。1 MiB 以内的 UTF-8 文本和源码文件以带文件名边界的块追加到草稿。浏览器可解码的视频会抽取四张 JPEG 画面并附上一句草稿说明，因此既有图片附件和视觉代理继续负责持久化与模型处理。

## Alternatives considered

**把每种二进制文件都持久化为新的附件类型** — 本次未采用。要让文件真正可用，还需要新的持久会话词汇、宿主 API、渲染契约、保留策略和模型专用文档解析器。

**将原始视频直接发送给模型路由** — 未采用。已配置的视觉代理接受图片，没有可互操作的视频输入。四张画面提供有界的视觉上下文，也不会保留大型不透明文件。

## Consequences

用户可以从输入栏选择图片、视频及常见文本或源码文件。PDF、Office、压缩包和其他二进制文档解析仍明确不支持，并显示清晰提示。视频依据采样画面理解，不包含音频或逐帧内容。

## Verification

InputBar 客户端测试覆盖打开选择器和插入选中的文本文件；客户端 TypeScript 程序与生产 Web 包均成功构建。
