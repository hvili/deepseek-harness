# Agent Note: 持久 shell 回退输出中裁掉已完成的标记

Status: implemented

[English](2026-08-22-persistent-shell-fallback-marker-leak.md) | 中文

## 问题

持久 shell 工具（bash 与 pwsh 孪生）通过扫描最新回滚页寻找本次调用的 END 标记来判定完成，再提取 START 与 END 之间的输出。真实 PTY 上，send 可能在提示符回到视口时结算，而刚写入的标记行尚未对该"最新页"读取可见，于是循环走入 prompt-completed 分支，`partialOutput` 返回 START 标记之后的全部内容——内部的 `__DSH_PERSISTENT_*_END_<nonce>:<status>` 行泄漏进面向模型的结果。在 Windows web lane 上表现为间歇性抖动（minimal-preset 场景驱动两次真实持久 pwsh 调用）；包级 stub 测试从未复现，因为其读取是同步的。

## 决策

`partialOutput` 的 start-marker 分支现在在"已完成的"END 标记处裁断——标记后紧跟下一行的状态数字——并把该状态作为退出码携带。回显的 wrapper 源码里标记拼写后面没有数字，回显永远不会触发裁断；只有真实的完成标记会。两个孪生做了同样的裁断（它们是有意的逐调用镜像），并且各自新增一个 stub 模式：offset 0 的读取只报告提示符、而完整回滚里已有结束的命令——泄漏的确切形状，从此有回归锁定。

## 备选方案

**改为修完成检测（重读直到标记可见）。** 检测将需要自带重试循环且无法限定回滚滞后视口的时长；裁断让任何交错都产出与完成路径相同的结果。

**在结果渲染器里剥标记。** 渲染器看到的是字符串而非标记对，无法区分内部标记与合法打印同样文本的命令。

## 后果

无论保留时机如何，结束的命令都精确返回其输出加退出状态——与完成路径一致——超时/中止路径保持部分语义（没有完成标记就没有裁断）。stub 模式以可执行的形式为两个孪生记载了这次保留竞态。
